# WindowPosition

Windowsのウィンドウ位置とサイズを保存し、タイトルをもとに自動で復元するタスクトレイ常駐アプリです。

対象ウィンドウをクリックするだけで登録できます。配布用アプリは、.NETランタイムを含む **単体の `WindowPosition.exe`** です。

## 主な機能

- **クリックでキャプチャ**：タイトル・位置・サイズを取得して登録。
- **2種類の適用モード**：「初回起動時のみ」と「常時追従」。
- **タイトルの完全一致・部分一致**：大文字・小文字を区別せず検索。
- **項目ごとのON/OFF**と、全体の一時停止・再開。
- **上下左右の端寄せ**：現在のサイズを保ち、対象モニターの端へ移動。座標と設定も同時に更新。
- **マルチモニター対応**：負の座標や異なる表示倍率を考慮し、物理ピクセルで管理。
- **トレイ常駐**：設定画面を閉じても監視を継続。exeの再実行で既存の設定画面を表示。
- **小型の設定ファイル**：exeと同じフォルダーの `settings.cfg` に保存。
- 登録一覧は、マウスホイール1目盛りで1項目ずつスクロール。

## 動作環境と起動

- Windows x64（Windows 11で動作確認）
- 設定を保存するため、exeのあるフォルダーへの書き込み権限が必要
- 単体exeの実行には、.NETランタイムの別途インストールは不要

このリポジトリにはソースコードを収録しています。exeは後述の[ビルド方法](#ビルド方法)で生成できます。

生成した `WindowPosition.exe` を書き込み可能なフォルダーに置いて起動してください。初回起動時に同じフォルダーへ `settings.cfg` を作成します。

```text
WindowPosition/
├── WindowPosition.exe
└── settings.cfg
```

## 使い方

### ウィンドウを登録する

1. **「ウィンドウをキャプチャ」** をクリックします。
2. 設定画面が一時的に隠れるので、登録したいウィンドウの中を左クリックします。
3. タイトル・位置・サイズが取得され、一覧へ登録されます。
4. 必要に応じて一致条件、適用モード、位置・サイズを編集し、**「保存して適用」** を押します。

新規登録は「完全一致」「初回起動時のみ」「ON」で自動保存されます。すでに同じ完全一致タイトルがある場合は、その項目の編集欄に取得した配置を入れます。「保存して適用」で確定してください。

キャプチャは `Esc` でキャンセルできます。開始から20秒で自動解除されます。選択に使ったクリックは対象アプリへ渡しません。

### 適用モード

| モード | 動作 |
| --- | --- |
| 初回起動時のみ | 新しく検出したウィンドウへ一度だけ配置を適用します。その後は自由に移動・リサイズできます。 |
| 常時追従 | 約0.5秒間隔で確認し、移動・リサイズされても登録した位置とサイズへ戻します。 |

「初回起動時のみ」は、Windowsへの初回ログインやアプリの初回インストールという意味ではありません。WindowPosition起動時にすでに開いている対象も、最初の検出で適用されます。対象ウィンドウやWindowPositionを起動し直した場合、登録内容を変更した場合、項目をOFFからONに戻した場合などにも再適用されます。

### 編集・保存

| 操作 | 動作 |
| --- | --- |
| 保存して適用 | 編集内容を保存します。項目がONかつ一時停止中でなければ、対象へ適用します。 |
| 今すぐ適用 | **保存済み**の位置・サイズを再適用します。未保存の編集内容は使いません。項目がONかつ一時停止中でない場合に使用できます。 |
| 現在の位置を取り込む | 対象の現在位置・サイズを編集欄へ読み込みます。保存はしません。 |
| 削除 | 登録だけを削除します。対象ウィンドウは閉じません。 |
| 項目のON/OFF | その項目の自動配置を切り替え、設定を即時保存します。 |
| 一時停止 | すべての自動配置を一時的に停止します。 |

### モニターの端へ揃える

「保存して適用」などのボタンの右側にある **↑・←・↓・→** を使います。

- 対象ウィンドウが現在あるモニターの、**タスクバーを除く作業領域**に揃えます。
- 保存したサイズではなく、**実際のウィンドウの現在サイズ**を保ちます。
- **「↑」→「←」** の順にクリックすると左上、**「↓」→「→」** の順にクリックすると右下へ揃います。
- 移動した位置と現在のサイズを編集欄・`settings.cfg` に即時反映します。
- 項目がOFF、または全体が一時停止中でも、矢印による手動配置は使えます。

矢印は、条件に一致する対象が1つだけで、最小化・最大化されていない場合に使えます。作業領域より大きいウィンドウは、勝手に縮小せずメッセージを表示します。

Windowsの見えないリサイズ枠を補正し、**見えている枠が端ぴったり**になるようにします。そのため、見た目が左上の `(0, 0)` でも保存座標は `(-8, 0)` などになる場合があります。複数モニターでは、各モニターの位置に応じたデスクトップ全体の座標になります。

矢印は配置だけを保存します。編集中のタイトルやモードは「保存して適用」で確定してください。

### トレイ常駐・終了

- **×ボタン**、または「トレイへ格納」で設定画面だけを閉じます。
- トレイアイコンのダブルクリックで、設定画面を再表示します。
- 右クリックメニューから、キャプチャ・一時停止・終了を操作できます。
- **完全に終了するには、トレイメニューの「終了」を選びます。**

### ログイン時に自動起動する

自動起動の登録は手動です。

1. `Win + R` を押し、`shell:startup` を開きます。
2. `WindowPosition.exe` の**ショートカット**を、このフォルダーに置きます。

次回ログイン時から起動します。解除する場合はショートカットだけを削除してください。exeを移動した場合は、ショートカットの参照先も変更する必要があります。

## 設定の保存・移行

- 保存先は常に **exeと同じフォルダーの `settings.cfg`** です。
- JSONではなく、チェックサム付きの小型バイナリ形式です。登録0件では8バイトです。
- 手作業でファイルを書き換えず、アプリの画面から編集してください。
- バックアップや別PCへの移行には `settings.cfg` をコピーします。移動先のアプリを終了してから配置してください。
- 読めない設定は警告を表示し、元のファイルを保持します。その状態から保存する際は、元のファイルを `settings.cfg.corrupt.*` として退避します。
- 設定ファイル・ビルド生成物・検証画像はGitの管理対象外です。

別PCでモニター構成が異なる場合は、復元位置を確認し、必要に応じて再キャプチャしてください。

## 診断ログ

exeと同じフォルダーの `WindowPosition.log` に、日時・プロセスID・起動・トレイ格納／再表示・終了理由・未処理例外を記録します。例外にはスタックトレースも含み、改行は `\n` として1行にまとめます。監視や設定保存のエラーも記録します。

- 1ファイル最大1 MiB。上限に達すると `WindowPosition.log.1` に退避し、合計2世代（約2 MiB）まで保持します。
- `START` は起動、`READY` は初期化完了、`WINDOW_HIDE` は常駐を続けたままの格納です。
- `EXIT` に終了理由を記録します。`TrayMenuExit` はトレイからの終了、`WindowsSessionEnding:...` はWindowsのセッション終了です。
- `UNHANDLED_EXCEPTION` は未処理例外です。`UNOBSERVED_TASK_EXCEPTION` は未観測のタスク例外で、必ずしもアプリ終了を意味しません。
- 前回の終了記録がない場合、次回起動時に `PREVIOUS_SESSION_INCOMPLETE` を記録します。強制終了・電源断などでは終了時刻や原因そのものは記録できず、この印だけでクラッシュとは断定できません。
- ログはGit管理対象外です。書き込みに失敗しても監視機能は継続します。ログには例外内のファイルパスなどが含まれる場合があります。

## 注意事項

- 識別には**ウィンドウタイトルだけ**を使用します。アプリの実行ファイル名では区別しません。
- 同じタイトルに一致するウィンドウは、通常の自動配置ではすべて対象です。複数の登録が同じウィンドウに一致する場合は、一覧の上にある有効な項目を優先します。
- タイトルが変わるアプリでは部分一致が便利ですが、短すぎる文字列は意図しない対象にも一致します。
- 最小化中のウィンドウは動かしません。通常表示に戻ると適用対象になります。
- 自動配置や「今すぐ適用」では、最大化を解除して登録した位置とサイズを適用する場合があります。
- Windowsの権限によって操作できない対象があります。管理者権限で動くアプリを操作する必要がある場合のみ、WindowPositionも管理者として実行してください。
- 対象アプリの最小サイズ制限などにより、指定したサイズを適用できない場合があります。
- 他のウィンドウ配置ツールで同じ対象を管理すると、配置が競合する可能性があります。

## ビルド方法

開発には **Windowsと.NET 10 SDK** が必要です。PowerShellから実行します。

```powershell
git clone https://github.com/HiroyukiTsunoda/WindowPosition.git
cd WindowPosition
dotnet build WindowPosition.slnx -c Release
```

### 単体exeを生成する

リポジトリのルートで実行します。

```powershell
.\scripts\Publish.ps1
```

`dist\WindowPosition.exe` を生成します。Windows x64向け、ランタイム同梱の単一ファイル形式です。初回のビルド・発行では、必要なパックの取得にネットワーク接続が必要になる場合があります。

発行先のexeを起動している場合は、トレイメニューから終了してから再発行してください。別の出力先も指定できます。

```powershell
.\scripts\Publish.ps1 -OutputDirectory .\publish
```

## テスト

### ロジック・設定保存

```powershell
dotnet run --project tests\WindowPosition.Tests\WindowPosition.Tests.csproj -c Release
```

追加のテストフレームワークを使わないコンソール形式のテストです。追従モード、設定の保存・破損検出、端寄せの計算などを検証します。

### 実デスクトップでの確認

通常のWindowsデスクトップ上で実行します。専用ウィンドウの表示・移動とマウス・キーボード入力を行うため、テスト中はほかの操作を控えてください。

```powershell
.\scripts\Test-Desktop.ps1
```

起動済みのWindowPosition本体まで確認する場合は、設定画面を表示してから実行します。

```powershell
.\scripts\Test-Desktop.ps1 -CheckApplication
```

実アプリの表示・トレイ常駐・キャプチャ・端寄せ・ON/OFF・保存を操作します。専用のテスト項目を追加し、終了時にその項目だけを削除して、設定ファイルが開始前と一致することを確認します。念のため実行前に `settings.cfg` をバックアップしてください。結果と画面画像は `artifacts\` に出力します。

ホイールだけを確認する場合は、少なくとも2項目分スクロールできる件数を登録し、設定画面を表示した状態で実行します。

```powershell
dotnet build tests\WindowPosition.Smoke\WindowPosition.Smoke.csproj -c Release
& .\tests\WindowPosition.Smoke\bin\Release\net10.0-windows\WindowPosition.Smoke.exe --check-wheel "Window Position" --output artifacts\wheel-smoke.json
```

```text
src/

tests/
├── WindowPosition.Tests/  ロジックと設定保存のテスト
└── WindowPosition.Smoke/  Windowsデスクトップ上の動作確認
scripts/

└── Test-Desktop.ps1       デスクトップ検証の実行
```
